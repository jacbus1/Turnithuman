# Turnithuman

[![Test and deploy GitHub Pages](https://github.com/jacbus1/Turnithuman/actions/workflows/pages.yml/badge.svg)](https://github.com/jacbus1/Turnithuman/actions/workflows/pages.yml)

English · [繁體中文](README.zh-TW.md)

A free, open-source AI writing signal detector that runs in your browser. Paste text or import documents to inspect model scores and get writing suggestions. No API key, account, or application backend is required.

**Not affiliated with or endorsed by Turnitin.** Scores cannot establish authorship or plagiarism and should not be used for grading or disciplinary decisions.

[Try the app](https://jacbus1.github.io/Turnithuman/) · [Editable Figma design](https://www.figma.com/design/U4hf2OKjWQy1gHVjgKwsfi)

![Turnithuman analysis workspace](public/turnithuman-analysis.png)

## Features

- React, TypeScript, Vite, and Web Worker model inference.
- Local q4 ONNX inference using Transformers.js and [mujian2026/multilingual-ai-text-detector](https://huggingface.co/mujian2026/multilingual-ai-text-detector).
- Initial download: approximately 181 MB of weights plus 17 MB of tokenizer data, in addition to application/runtime assets. Browser caching can reduce subsequent downloads.
- English is the primary supported language; Chinese and mixed-language results are experimental.
- TXT, MD, DOCX, text-layer PDF, and PPTX imports up to **50 MiB** (shown as “50 MB” in the interface).
- Analysis accepts **20–100,000 characters**. A file below the upload limit can still exceed the extracted-text limit.
- Segment scores, heuristic labels, and rule-based writing advice.
- Manual editing and reanalysis; no generative rewriting feature or guarantee of lower third-party detector scores.

## How to use

1. Paste writing or import a supported document.
2. Select **Analyze writing** and wait for the initial model download.
3. Review segment signals and writing advice.
4. Edit the draft and select **Analyze edited draft**.
5. Clear the workspace or refresh to remove submitted text.

## Scores

| Metric or label | Meaning |
| --- | --- |
| `modelAiScore` | Average model AI score weighted by estimated core-text tokens |
| `estimatedAiShare` | Share of estimated core-text tokens in segments scoring at least 0.65 |
| Likely human | Score below 0.35 |
| Uncertain | Score at least 0.35 and below 0.65 |
| Likely AI | Score at least 0.65 |

Thresholds are product heuristics, not Turnitin-calibrated thresholds. Model scores are not calibrated probabilities of authorship. Estimated AI share does not measure how much text was actually generated by AI.

The current segmenter estimates token counts instead of using the model tokenizer. Inference truncates to 384 tokens, so long or unusual inputs may lose content before classification. This needs further work.

Short English inputs (under 100 words) and Chinese/mixed inputs (under 300 non-whitespace characters) receive warnings.

## Accuracy limitations

The upstream evaluation covers a small, in-domain dataset. Performance on new generators, literary writing, translations, edited content, and specialist subjects is not established. Read the [model card](https://huggingface.co/mujian2026/multilingual-ai-text-detector), [Turnitin documentation](https://guides.turnitin.com/hc/en-us/articles/22774058814093-Using-the-AI-Writing-Report), and [NAACL 2025 evaluation](https://aclanthology.org/2025.findings-naacl.271/).

Earlier exploratory checks reported five newly generated passages labeled AI, ten correctly labeled answers from five human/ChatGPT pairs in the **HC3 training split**, and four false AI labels among five excerpts from Project Gutenberg works.

These are **not a held-out accuracy benchmark**. HC3 is related to the upstream training data; overlap has not been excluded. Gutenberg selection included introductory material and a chapter synopsis. The checks used direct truncated model calls, not the full document pipeline, and did not save immutable fixtures and full results in this repository. The counts must not be interpreted as general accuracy.

## Documents and privacy

- DOCX: Mammoth extracts text.
- PDF: PDF.js extracts selectable text with page markers; image-only PDFs require OCR, which is not provided.
- PPTX: JSZip extracts text with slide markers. Current numeric filename sorting can differ from actual presentation order in reordered decks.
- Document content is rendered as React text nodes rather than executable HTML.
- Submitted text is not persisted across refreshes.
- Network access loads website/runtime assets and public model files. Hosting services may receive ordinary connection metadata.

See [Privacy](PRIVACY.md) and [Third-party notices](THIRD_PARTY_NOTICES.md).

## Local development

Requires Node.js **22.13 or later**.

```bash
npm ci
npm run dev
```

Vite uses the fixed base path `/Turnithuman/`. The usual local URL is `http://localhost:5173/Turnithuman/`.

```bash
npm run lint
npm run type-check
npm test
npx playwright install chromium-headless-shell
npm run test:e2e
npm run build
```

Regular CI does not download the large model. Explicitly run the real-model Node smoke test with:

```bash
npm run test:model
```

It checks model loading and short English/Chinese inference, not accuracy or browser compatibility. Current E2E tests exercise basic import/edit/analyze flows with mocked inference.

## Deployment

Pushes to `main` run lint, type checking, unit tests, browser tests, and a production build before deploying to GitHub Pages. No custom domain is configured.
